# Automated Tests and Continuous Integration

CTGTRec uses a lightweight automated test suite for source validation and the
reproducibility-critical preprocessing path. The suite intentionally does not
run four full datasets, three-seed GPU training, or every baseline in GitHub
Actions.

## Local test environment

From the repository root, create or activate Python 3.10 and install:

```bash
pip install -r requirements-ci.txt
```

Run the complete lightweight suite:

```bash
python -m pytest
```

The test dependencies are separate from `requirements.txt` so CI does not need
to download PyTorch, PyTorch Geometric, or CUDA wheels merely to validate data
splitting and graph construction.

## What is tested

The suite checks:

- Python syntax for files under `preprocessing/` and `src/`;
- YAML configuration, workflow, and `CITATION.cff` parsing;
- strict rejection of unknown `src/main.py` command-line options;
- per-user temporal sorting by `(timestamp, original_record_order)`;
- exactly one validation and one test interaction per eligible user;
- rejection of user histories shorter than three interactions;
- user-normalized temporal distances, including zero-span users;
- train-only continuous-time graph construction;
- summation of duplicate user-item temporal weights;
- raw/normalized graph symmetry and normalization agreement;
- exclusion of validation and test interactions from graph edges;
- feature-row and mapping-row alignment checks;
- comma-separated mapping files generated by raw preprocessing;
- backward-compatible reading of legacy tab-separated mapping files;
- preservation of string identifiers such as ASINs with leading zeros;
- rejection of fractional, negative, non-finite, duplicate, or non-contiguous
  mapping IDs.

## GitHub Actions

The workflow is stored at:

```text
.github/workflows/ci.yml
```

It runs on:

- pushes to `main` and `cleanup/reproducibility`;
- pull requests;
- manual workflow dispatch.

The same suite is executed on Ubuntu 24.04 and Windows Server 2022 with Python
3.10.20. The workflow has read-only repository permissions and cancels older
runs for the same ref when a newer commit is pushed.

## Delimiter policy

New raw preprocessing outputs use:

```text
<dataset>.inter       tab-separated
u_id_mapping.csv      comma-separated
i_id_mapping.csv      comma-separated
```

Mapping readers detect both comma and tab formats from required header columns.
This keeps existing notebook-generated TSV mappings usable while making new
`.csv` files conform to their extension. Unsupported or ambiguous headers fail
with an explicit error.

The continuous-time graph manifest records the detected mapping delimiter so a
reproduction run can be audited later.

## Tests not covered by lightweight CI

Before a release or paper-result refresh, run these separately on the target GPU
machine:

1. generate all four strict temporal splits;
2. regenerate all four dataset-specific raw and normalized time graphs;
3. run CTGTRec with seeds `999`, `2024`, and `3407` on every dataset;
4. confirm each seed restores the best validation checkpoint;
5. confirm one final test evaluation per seed;
6. compare `summary.json` and `summary.csv` with the reported tables;
7. smoke-test every included baseline used in the manuscript.

Passing GitHub Actions means the lightweight contracts are intact; it does not
claim that full GPU experiments have been rerun.
